# 학생용 챗봇 실행·배포 안내

「AI와 논쟁하며 탄소 저감 과학기술 제안하기」 수업 챗봇입니다. 학생은 한 주소에서 차시(1차시 기술 탐구, 2차시 비판적 토론, 3차시 설계 심사)를 골라 대화합니다. 서버가 Anthropic API 키와 차시별 시스템 프롬프트를 보관합니다.

```
학생 브라우저 ──(내 글 + 서명된 대화 토큰)──▶ 이 서버 ──▶ Anthropic API
                                              └─(선택)─▶ Supabase 대화 기록(교사만 읽음)
```

- **키와 시스템 프롬프트는 서버에만 있습니다.** 브라우저로 나가지 않습니다.
- **대화 기록은 서버가 서명한 토큰**으로 주고받아서, 학생이 브라우저 개발자 도구로 챗봇의 말을 위조해 끼워 넣을 수 없습니다.
- 수업 코드와 여러 겹의 요청 제한(아래 3번)이 있어서 **우연히 주소를 안 사람**이 비용을 쓰기는 어렵습니다. 하지만 수업 코드를 아는 학생이 마음먹고 쓰는 것까지 완전히 막을 수는 없습니다. **진짜 비용 상한은 Anthropic 개발자 콘솔의 월 사용 한도**로 반드시 따로 거세요.

## 0. 먼저 알아 두세요

- 자동 테스트는 모의 API로 합니다(서버 연결, 스트리밍, 위조 방지, 제한, 화면). 실제 Anthropic API 점검(`npm run check:api`)은 2026년 10월 12일 교사 PC에서 `claude-opus-5-5`로 통과했습니다. 모델이나 설정을 바꾸면 다시 돌려 보세요.
- 2차시 프롬프트는 실제 API로 아직 시험하지 않았습니다. `npm run check:api -- 2`로 확인하고, 실제 학생처럼 끝까지 대화해 보세요.
- 3차시 프롬프트도 실제 API로 아직 시험하지 않았습니다(모의 API로 8단계 표시와 기록만 확인했습니다). `npm run check:api -- 3`으로 확인하고, 학생처럼 8단계 끝까지 대화해 보세요. 특히 4단계 심사 질문에 해결 방법이 숨어 있지 않은지, 6·7단계에서 수정안을 대신 써 주지 않는지 확인해 주세요.
- Vercel용 설정은 Vercel CLI의 `vercel build`로 빌드 결과(함수 인식, 프롬프트 파일 포함, 공개 파일 범위)를 확인했고, 빌드된 함수를 모의 API에 붙여 실행해 봤습니다. 실제 Vercel 배포에서의 동작은 첫 배포 뒤 3-1의 4번으로 확인해야 합니다.
- 프롬프트 시험은 모델을 에이전트가 연기하는 시뮬레이션으로 했습니다. 선택하신 모델로 실제 학생 대화를 몇 번 해 보고 정답을 흘리지 않는지 직접 확인해 주세요.

## 1. 내 PC에서 실행하기 (개발·시험용)

**준비물**
- Node.js 22.9 이상(최신 LTS 권장). 설치 후 터미널(윈도우는 PowerShell 또는 명령 프롬프트, 맥은 터미널)에서 `node --version`으로 확인하세요. 시작 명령이 쓰는 `--env-file-if-exists` 옵션 때문에 이 버전이 필요합니다.
- 이 저장소 내려받기: `git clone`을 쓰거나, GitHub 저장소 페이지에서 ZIP으로 받아 압축을 풀어도 됩니다.
- Anthropic API 키: Anthropic 개발자 콘솔에서 발급합니다. API 사용은 Claude 구독과 별도로 결제됩니다. 콘솔에서 이 프로젝트 전용 키를 새로 만들고 **월 사용 한도**를 걸어 두세요. 화면 이름은 바뀔 수 있으니 콘솔의 안내를 따르세요.

**순서**
1. 저장소 폴더에서 패키지를 설치합니다.
   ```
   npm install
   ```
2. 설정 파일을 만듭니다.
   - Mac/Linux: `cp .env.example .env`
   - Windows(PowerShell): `Copy-Item .env.example .env`
   - PowerShell에서 막히면 명령 프롬프트(cmd)에서 `copy .env.example .env`
3. `.env`를 열어 값을 채웁니다. **이 파일은 git에 올라가지 않습니다.** 키는 이 파일에만 쓰세요.
   - `.env`는 점(`.`)으로 시작하는 파일이라 탐색기나 Finder에서 안 보일 수 있습니다. 맥은 Finder에서 `Cmd+Shift+.`로 숨김 파일을 보이게 하고, 윈도우는 탐색기의 "파일 확장명" 보기를 켜세요.
   - 윈도우 메모장으로 저장할 때는 파일 형식을 "모든 파일", 인코딩을 UTF-8로 하고 이름이 `.env`인지 확인하세요(`.env.txt`가 되면 안 됩니다).
   - `ANTHROPIC_API_KEY` : Anthropic API 키
   - `SESSION_SECRET` : 32자 이상 무작위 문자열. 만드는 명령은 `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
   - `ACCESS_CODE` : 학생에게 알려 줄 수업 코드. **추측하기 어려운 8자 이상(영문+숫자)** 으로 정하고 수업마다 바꾸세요. 짧거나 비어 있으면 서버가 시작할 때 경고합니다.
4. **실제 API 점검**을 돌립니다. 키, 모델, 스트리밍, 프롬프트 캐시, 2턴 대화를 확인하고 통과/실패를 알려 줍니다. API 호출이 2번 일어나며 비용은 모델에 따라 다릅니다. 2·3차시는 뒤에 `-- 2`, `-- 3`을 붙입니다.
   ```
   npm run check:api
   npm run check:api -- 2
   npm run check:api -- 3
   ```
5. 서버를 켭니다.
   ```
   npm start
   ```
   브라우저에서 `http://localhost:3000`을 엽니다. 포트가 이미 쓰이고 있으면 서버가 시작하지 못했다는 안내를 내고 종료합니다. 이때는 `.env`에 `PORT=3001`처럼 다른 번호를 적으세요.

키 없이 화면만 보고 싶으면 `npm run demo`를 쓰세요. 정해진 문장으로 답하는 모의 응답이라 진짜 챗봇이 아닙니다.

## 2. 대화 기록 저장(선택)

교사가 학생 대화를 나중에 읽거나, 위기 신호가 감지된 대화를 먼저 보려면 켭니다. 켜면 학생은 대화를 시작하기 전에 **학번(숫자 5자리)과 이름**을 반드시 입력하고, 모든 기록 줄에 **학번·이름·차시**가 함께 남습니다. 끄면 학번·이름을 묻지도 저장하지도 않습니다.

1. Supabase 프로젝트를 준비합니다(2-1과 같은 프로젝트를 쓰면 됩니다).
2. SQL Editor에서 `supabase/schema.sql` 전체를 실행합니다. **이전에 실행한 적이 있어도 한 번 더 실행하세요**(기록에 학번·이름 열이 더해지고, 3차시 8단계를 받도록 단계 범위가 1~8로 넓어집니다. 여러 번 실행해도 안전합니다).
   - 단계 범위를 넓히기 전에 3차시를 쓰면, 7·8단계 기록은 단계 칸만 빈 채로 남고 서버 로그에 `schema.sql을 다시 실행해 주세요`가 찍힙니다.
3. 환경 변수(Vercel이면 Settings → Environment Variables, 내 PC면 `.env`)에 `LOG_CHATS=true`를 넣습니다.
   - 2-1에서 `SUPABASE_URL`과 `SUPABASE_SECRET_KEY`를 이미 넣었다면 **이것 하나만** 더하면 됩니다. 서버는 비밀 키로 기록합니다.
   - 비밀 키 없이 공개용 키(`SUPABASE_PUBLISHABLE_KEY`)만 넣어도 기록할 수 있습니다(공개용 키는 기록 표에 쓰기만 허용되어 있습니다).
4. 다시 배포하거나 서버를 다시 켭니다. 학생 화면 시작 카드에 "대화 내용은 아래 학번·이름과 함께 저장되어 선생님이 볼 수 있어요" 안내와 학번·이름 칸이 나타납니다.
5. 기록은 Supabase 대시보드의 Table Editor(`chat_logs`)나 SQL Editor에서 봅니다. 학번별·차시별 조회 예시는 `supabase/schema.sql` 맨 아래에 있습니다.

**결정하고 확인하실 것**
- **학번과 실명, 학생이 쓴 글이 함께 저장됩니다.** 학교의 개인정보 처리 지침과, 학생·보호자에게 알리거나 동의를 받아야 하는지를 **학교에 확인한 뒤** 켜세요. 이 문서는 법률 안내가 아닙니다.
- 학번·이름은 학생이 직접 입력하는 값이라 서버가 진짜인지 확인하지 않습니다. 다른 학생의 학번·이름을 쓸 수도 있으니 수업에서 안내해 주세요.
- 학생이 대화 중에 다른 개인 정보를 쓸 수도 있습니다(화면은 쓰지 말라고 안내합니다).
- 보관 기간을 정하고 지나면 지우세요(삭제 예시는 `schema.sql`에 있습니다).
- 위기 신호 표시는 **단순한 키워드 검사라서 놓치는 경우가 많습니다.** 안전장치가 아니라, 교사가 먼저 읽을 대화를 고르는 보조 표시입니다. 실시간 알림도 없으므로 주기적으로 확인해야 합니다.
- 기록 표는 공개용 키로는 읽거나 지울 수 없습니다. 공개용 키로 기록하는 경우, 그 키를 아는 사람이 가짜 기록을 추가할 수는 있습니다. 비밀 키로 기록하면 이 걱정이 줄어듭니다(비밀 키 관리는 2-1 참고).

## 2-1. 학번으로 1차시 정리 카드 저장(선택)

켜면 1차시 정리 카드 아래에 **학번으로 저장** 칸이 생기고, 2차시 시작 화면에서 **학번으로 불러오기**를 할 수 있습니다. 끄면 학생은 지금처럼 '정리 카드 복사'로 카드를 보관했다가 2차시 시작 화면에 붙여 넣습니다(이 방법은 켜도 그대로 쓸 수 있습니다).

1. Supabase 프로젝트를 준비합니다(2번과 같은 프로젝트를 써도 됩니다).
2. SQL Editor에서 `supabase/schema.sql` 전체를 실행합니다. 이미 실행한 적이 있어도 다시 실행하면 됩니다(여러 번 실행해도 안전합니다).
3. Supabase 대시보드의 **Settings → API Keys**에서 **비밀 키(secret key, `sb_secret_`로 시작)**를 확인하거나 새로 만듭니다.
4. 환경 변수를 넣습니다. Vercel이면 Settings → Environment Variables(값은 Secret으로), 내 PC면 `.env`입니다.

   | 이름 | 값 |
   |---|---|
   | `SAVE_CARDS` | `true` |
   | `SUPABASE_URL` | 프로젝트 URL |
   | `SUPABASE_SECRET_KEY` | 3번의 비밀 키 |

5. 다시 배포(Vercel)하거나 서버를 다시 켭니다. 1차시에서 카드를 저장하고 2차시에서 불러와 보세요.
6. 저장된 카드는 Supabase의 Table Editor(`lesson1_cards`)나 SQL Editor에서 봅니다. 학번별 조회와 삭제 예시는 `supabase/schema.sql` 맨 아래에 있습니다.

**결정하고 확인하실 것**
- **학번은 추측하기 쉽습니다.** 수업 코드를 아는 사람은 다른 학생의 학번을 넣어 **그 학생의 카드를 볼 수 있고**, 다른 학생의 학번으로 **카드를 저장할 수도 있습니다**(2차시에서는 가장 최근 것을 불러옵니다). 이전에 저장한 카드는 지워지지 않고 남으므로, 교사가 SQL Editor에서 확인하고 잘못 저장된 줄을 지울 수 있습니다. 화면은 불러온 뒤 "내 카드가 맞는지 확인해 주세요"라고 안내합니다. 이것이 수업에서 문제가 된다면 학번과 함께 학생이 정한 비밀번호를 쓰는 방식으로 바꿀 수 있습니다.
- 학번과 학생이 쓴 내용이 함께 저장되므로, 2번과 마찬가지로 **학교의 개인정보 지침을 확인한 뒤** 켜고, 보관 기간을 정해 지우세요.
- **비밀 키는 행 수준 보안(RLS)을 모두 우회하는 강한 키입니다.** 서버의 환경 변수에만 두고 채팅·GitHub·문서에 붙여넣지 마세요. 새어 나갔다고 생각되면 Supabase에서 그 키를 지우고 새로 만드세요. Supabase는 비밀 키를 브라우저에서 쓰면 거절합니다.
- **Supabase 무료(Free) 요금제는 1주일 동안 데이터베이스 활동이 적으면 프로젝트를 일시 정지합니다**(2026년 10월 Supabase 문서 기준). 1차시와 2차시 사이가 1주일 넘게 벌어지면, 2차시 수업 전에 Supabase 대시보드에서 프로젝트가 정지되지 않았는지 확인하고, 정지되어 있으면 **Resume project**를 눌러 다시 켜세요. 정지된 동안에도 학생은 카드를 붙여 넣어 2차시를 시작할 수 있습니다.
- 카드 테이블은 공개용(publishable) 키로는 읽기도 쓰기도 할 수 없게 만들어져 있습니다(`schema.sql`).
- 서버는 챗봇이 실제 1차시 대화에서 보여 준 카드만 저장합니다(서명된 대화 기록 안에 그 카드가 있어야 합니다).

## 3. 학생이 쓰도록 올리기 (호스팅)

### 3-1. Vercel에 올리기

이 저장소에는 Vercel용 진입점(`index.js`)과 설정(`vercel.json`)이 들어 있습니다. Vercel은 `public/`의 화면 파일을 직접 보내고, `/api`로 시작하는 요청만 `index.js`를 함수로 실행해 처리합니다. 내 PC에서는 지금처럼 `npm start`(`server/index.js`)를 씁니다. 아래 내용은 2026년 10월 Vercel 문서 기준입니다.

1. Vercel에서 이 GitHub 저장소를 가져와(Import) 프로젝트를 만듭니다. 프레임워크는 `vercel.json`이 Express로 정하므로 따로 고르지 않아도 됩니다.
2. 프로젝트의 **Settings → Environment Variables**에 아래 값을 넣고, 환경은 **Production**을 고릅니다.

   | 이름 | 값 | 필수 |
   |---|---|---|
   | `ANTHROPIC_API_KEY` | API 키 | 예 |
   | `SESSION_SECRET` | 32자 이상 무작위 문자열 | 예 |
   | `ACCESS_CODE` | 수업 코드(8자 이상) | **강력 권장**. 주소가 인터넷에 공개됩니다. |
   | `CHATBOT_MODEL`, `CHATBOT_EFFORT`, 제한 값들 | 3-2의 표와 같음 | 아니오 |
   | `SAVE_CARDS`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY` | 2-1 참고 | 아니오 |

   - `NODE_ENV`와 `TRUST_PROXY`는 넣지 않아도 됩니다. `index.js`가 항상 운영 기준으로 설정을 검사하고, Vercel이 실제 접속 주소를 알려 주므로 프록시 설정도 알아서 합니다.
   - 값을 **Secret**으로 저장하면 저장한 뒤에는 다시 볼 수 없습니다. 키와 `SESSION_SECRET`은 Secret으로 두고, 수업 코드는 나중에 확인할 수 있게 Config로 두어도 됩니다.
3. **환경 변수를 넣거나 바꾼 뒤에는 다시 배포해야 적용됩니다.** 프로젝트의 Deployments 화면에서 가장 최근 배포를 다시 배포(Redeploy)하세요. 화면 이름은 바뀔 수 있으니 Vercel의 안내를 따르세요.
4. 브라우저에서 `https://내-주소/api/health`를 엽니다.
   - `{"ok":true,...}`가 나오면 서버가 동작하는 것입니다. 첫 화면에서 수업 코드를 넣고 대화해 보세요.
   - `"error":"server_config"`가 나오면 필수 환경 변수가 빠졌거나 틀린 것입니다. 프로젝트의 **Logs**에서 `[설정 오류]` 줄을 찾으면 무엇이 문제인지 나옵니다.
   - `NOT_FOUND`가 나오면 `index.js`와 `vercel.json`이 들어 있지 않은 예전 코드로 배포된 것입니다.
5. 이후에는 `main` 브랜치에 올라간 변경이 자동으로 다시 배포됩니다. 프롬프트를 고칠 때도 같으니 수업 시간 밖에 올리세요(5번 참고).

**Vercel에서 달라지는 점**
- 요청 제한과 하루 상한을 **함수 인스턴스마다 따로** 셉니다. 접속이 많아 인스턴스가 늘면 그만큼 느슨해지고, 인스턴스가 새로 뜨면 초기화됩니다. 수업 코드와 대화 위조 방지는 그대로 동작합니다. 실제 비용 상한은 Anthropic 콘솔의 월 한도입니다.
- 응답 하나는 최대 300초(무료 Hobby 요금제)까지 걸릴 수 있습니다.
- Vercel 문서는 무료 Hobby 요금제를 "non-commercial personal use only"(비상업적 개인 용도)로 제한합니다. 수업에 쓰는 것이 여기에 해당하는지는 학교에서 판단하거나 Vercel 지원팀에 문의하세요.
- 브랜치나 PR마다 만들어지는 Preview 배포에는 Preview 환경의 변수가 쓰입니다. 넣지 않았다면 그 주소에서는 설정 오류 안내가 나옵니다.

### 3-2. 그 밖의 Node.js 호스팅

이 서버는 일반적인 Node.js 앱이라서, Node 앱을 올릴 수 있는 호스팅 서비스라면 대부분 같은 방식으로 올릴 수 있습니다. 서비스마다 화면이 달라서 여기서는 공통 절차만 적습니다.

| 항목 | 값 |
|---|---|
| 런타임 | Node.js 22.9 이상 |
| 설치 명령 | `npm install` |
| 시작 명령 | `npm start` |
| 포트 | 서비스가 주는 `PORT` 환경 변수를 서버가 읽습니다 |
| 상태 확인 주소 | `/api/health` |

**호스팅의 환경 변수(비밀 값 설정 칸)에 넣을 것** (`.env` 파일을 올리지 마세요)

| 이름 | 값 | 필수 |
|---|---|---|
| `NODE_ENV` | `production` | 예 |
| `ANTHROPIC_API_KEY` | API 키 | 예 |
| `SESSION_SECRET` | 32자 이상 무작위 문자열(여러 대로 돌리면 모두 같은 값) | 예 |
| `ACCESS_CODE` | 수업 코드(8자 이상 권장) | 강력 권장 |
| `TRUST_PROXY` | `1` | 호스팅 서비스 뒤에서 실행할 때 |
| `CHATBOT_MODEL`, `CHATBOT_EFFORT` | 기본은 `claude-opus-5-5`, `medium` | 아니오 |
| `LOG_CHATS`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY`(또는 `SUPABASE_PUBLISHABLE_KEY`) | 2번 참고 | 아니오 |
| `SAVE_CARDS`, `SUPABASE_SECRET_KEY` | 2-1 참고 | 아니오 |

- `NODE_ENV=production`에서는 `ANTHROPIC_API_KEY`, `SESSION_SECRET`이 없으면 **서버가 시작하지 않습니다.** 설정 실수를 미리 알려 주기 위해서입니다.
- `TRUST_PROXY`를 빼면 모든 학생이 같은 주소로 보여서 주소별 제한이 한꺼번에 걸릴 수 있습니다.
- 주소가 `https://`로 열리는지 확인하세요.
- 서버 로그에는 대화 내용을 일부러 남기지 않습니다. 세션 번호 앞 8자리, 정지 사유, 토큰 사용량, 오류 종류만 남깁니다.

**요청 제한과 상한** (3-1, 3-2 공통. 모두 선택 설정이며 기본값이 있습니다)

| 이름 | 기본값 | 의미 |
|---|---|---|
| `DAILY_REQUEST_CAP` | 3000 | **전체 학생 합산** 하루 요청 상한(한국 시간 자정에 초기화, 서버를 다시 켜도 초기화). Anthropic이 실패한 요청은 세지 않습니다. 여러 반이 같은 날 쓰면 늘리세요. |
| `RATE_PER_SESSION_PER_MIN` | 8 | 한 대화가 1분에 보낼 수 있는 횟수 |
| `RATE_PER_IP_PER_MIN` | 240 | 같은 주소(학교 와이파이는 보통 하나)에서 1분에 Anthropic까지 가는 요청 수 |
| `NEW_CONVERSATIONS_PER_IP_PER_MIN` | 60 | 같은 주소에서 1분에 새로 시작할 수 있는 대화 수(학생 30명이 동시에 시작해도 되는 값) |
| `BAD_CODE_PER_IP_PER_MIN` | 30 | 같은 주소에서 1분에 틀린 수업 코드를 몇 번까지 받을지. 넘으면 맞는 코드도 1분 안팎 받지 않습니다. |
| `MAX_CONCURRENT_STREAMS` | 40 | 동시에 진행되는 응답 수 상한 |
| `MAX_TURNS` | 80 | 한 대화의 최대 주고받기 횟수. 남은 횟수가 5번 이하가 되면 학생 화면에 미리 알립니다. |
| `MAX_STATE_CHARS` | 1500000 | 대화 정보(압축해서 서명한 대화 기록)의 최대 글자 수. 80%를 넘으면 미리 알리고, 95%를 넘으면 답을 만들기 전에 멈춥니다. 브라우저 저장 공간을 생각해 크게 늘리지 마세요. |
| `MAX_STUDENT_CHARS` | 2000 | 학생 메시지 최대 글자 수(3차시 설계 양식을 한 번에 쓸 수 있게) |
| `SESSION_MAX_AGE_HOURS` | 12 | 마지막 응답 뒤 이 시간이 지나면 이어서 대화할 수 없음 |
| `CHATBOT_MAX_TOKENS` | 16000 | 응답 하나의 최대 길이(생각 과정 포함) |
| `CARD_REQUESTS_PER_IP_PER_MIN` | 120 | 같은 주소에서 1분에 정리 카드를 저장·불러오는 횟수(2-1) |

## 5. 프롬프트를 고치려면

차시별 프롬프트는 `prompts/lesson1_system_prompt.md`, `prompts/lesson2_system_prompt.md`, `prompts/lesson3_system_prompt.md`입니다. 수정하고 서버를 다시 켜면(Vercel은 `main`에 올리면) 됩니다. 서버는 시작할 때 파일을 읽고, 내용의 짧은 해시를 차시별 **프롬프트 버전**으로 기록합니다(`/api/health`의 `promptVersions`와 대화 기록의 `prompt_version`). 어느 버전으로 한 대화인지 나중에 알 수 있습니다.

- 학생 화면의 차시 이름, 시작 안내, **단계 이름**은 `server/lessons.js`에 있습니다. 프롬프트의 `[단계 n/N · 이름]` 머리글(1·2차시는 N=6, 3차시는 N=8)과 단계 수·이름을 같게 맞춰 주세요. 단계 수를 9 이상으로 늘리려면 `supabase/schema.sql`의 단계 범위와 머리글을 읽는 규칙(한 자리 숫자)도 함께 고쳐야 합니다.
- 한 차시의 프롬프트를 바꾸면 그 차시의 진행 중인 대화만 이어지지 않습니다. 다른 차시는 영향이 없습니다.

- **프롬프트나 모델(`CHATBOT_MODEL`)을 바꾸면 진행 중이던 학생 대화는 이어지지 않습니다.** 학생 화면에 "수업 내용이 업데이트되어 이 대화를 이어갈 수 없어요"가 나오고 처음부터 다시 시작해야 하므로, **수업 시간 밖에서** 바꾸세요.
- 바꾼 뒤에는 위 점검표의 시험을 다시 해 보세요.

## 6. 문제가 생기면

학생 화면에 나오는 문구별로 정리했습니다. 서버 로그에서 `[chat] 실패(...)`나 `[FLAG]` 줄을 찾으세요.

| 학생 화면의 문구 | 원인과 확인할 것 |
|---|---|
| 챗봇 서버 설정에 문제가 있어요 | API 키가 없거나 틀렸거나 권한이 없습니다. 로그의 `server_config`. Vercel이면 필수 환경 변수가 빠졌을 때도 나오며, Logs의 `[설정 오류]` 줄에 무엇이 빠졌는지 나옵니다(3-1). |
| 챗봇 사용 한도에 도달했어요 | Anthropic 결제나 월 사용 한도 문제입니다. 로그의 `billing`. 콘솔의 한도와 잔액을 확인하세요. |
| 지금 이용하는 사람이 많아요 / 지금 접속한 학생이 많아요 | Anthropic의 일시 과부하나 요청 한도, 또는 동시 응답·주소별 제한입니다. **자동으로 다시 시도하지 않으니** 학생이 글을 다시 보내면 됩니다(쓴 글은 입력창에 남아 있습니다). 자주 나오면 위 제한 값과 콘솔의 한도를 확인하세요. |
| 오늘 사용할 수 있는 횟수를 모두 썼어요 | `DAILY_REQUEST_CAP`에 도달했습니다. 값을 늘리거나 서버를 다시 켜면 초기화됩니다(다음 날 자정에도 초기화). |
| 수업 코드를 너무 많이 틀렸어요 | 같은 주소에서 틀린 코드를 `BAD_CODE_PER_IP_PER_MIN` 넘게 보냈습니다. 1분쯤 기다리면 풀립니다. |
| 수업 코드가 맞지 않아요 | 코드를 다시 확인하세요. `.env`나 호스팅의 `ACCESS_CODE`와 학생에게 알린 값이 같은지 보세요. |
| 수업 내용이 업데이트되어 이 대화를 이어갈 수 없어요 | 프롬프트나 모델을 바꾼 뒤입니다(5번). "처음부터 다시"로 새로 시작하게 하세요. |
| 대화 정보가 올바르지 않아요 / 만료됐어요 | `SESSION_SECRET`이 바뀌었거나(설정하지 않아 임시 값을 쓰는 경우), 마지막 응답 뒤 12시간이 지난 경우입니다. 운영에서는 고정 값을 쓰세요. |
| 요청을 처리하지 못했어요 | 로그의 `bad_request` 메시지를 보세요. 모델 이름이나 설정이 계정에서 받아들여지지 않을 때 나올 수 있습니다. `npm run check:api`로 확인하세요. |
| 아직 열리지 않은 차시예요 / 다른 차시의 대화 정보예요 | 화면을 새로고침하고 차시를 다시 고르거나 "처음부터 다시"를 누르게 하세요. |
| 학번으로 정리 카드를 저장하는 기능이 꺼져 있어요 | `SAVE_CARDS`가 꺼져 있습니다(2-1). 켜지 않을 거라면 카드를 복사·붙여넣기로 옮기게 하세요. |
| 이 학번으로 저장된 1차시 정리 카드가 없어요 | 1차시에서 그 학번으로 저장하지 않았거나 학번을 잘못 입력했습니다. 복사해 둔 카드를 붙여 넣어도 됩니다. |
| 정리 카드를 저장하거나 불러오지 못했어요 | Supabase 연결 문제입니다. 먼저 Supabase 프로젝트가 일시 정지되지 않았는지 보세요(무료 요금제, 2-1). 그다음 로그의 `[cards]` 줄을 보고 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `schema.sql` 실행 여부를 확인하세요. |
| 챗봇이 대화에서 만든 정리 카드만 저장할 수 있어요 | 정리 카드 아래의 저장 칸을 썼는데도 나온다면, 대화가 12시간보다 오래되었거나 서버 설정(`SESSION_SECRET`)이 바뀐 경우입니다. 카드를 복사해서 2차시에 붙여 넣게 하세요. |
| 대화가 너무 길어져 이 대화로는 더 이어갈 수 없어요 | 한 대화가 `MAX_TURNS`나 `MAX_STATE_CHARS`에 닿았습니다. 로그에 `[chat] 대화 길이 한도` 줄이 남습니다. 학생은 안내 옆의 **이어서 새 대화 시작**을 누르면 됩니다(아래 '이어서 새 대화' 참고). 쓴 글은 입력창에 남아 있다가 함께 보내집니다. |
| 수업 내용이 업데이트되어 이 대화를 그대로 이어갈 수 없어요 / 대화가 너무 오래되어 만료됐어요 | 프롬프트·모델을 바꿨거나 마지막 응답 뒤 12시간이 지났습니다. 이때도 **이어서 새 대화 시작**으로 이어서 할 수 있습니다. |
| 연결이 불안정해요 | 서버와 Anthropic 사이의 네트워크 문제입니다. 잠시 뒤 다시 보내게 하세요. |
| 답변을 만들지 못했어요 | 분류되지 않은 오류입니다. 로그의 `generic` 줄을 보세요. |
| 답변이 너무 길어서 중간에 끊겼어요 | 응답이 `CHATBOT_MAX_TOKENS`에 걸렸습니다. 값을 늘리세요. |
| (서버가 시작하지 않음) 포트를 다른 프로그램이 쓰고 있어요 | 이미 켜 둔 서버가 있거나 다른 프로그램이 같은 포트를 씁니다. `PORT`를 바꾸세요. |

## 7. 알려진 한계

- 요청 제한과 하루 상한은 서버 메모리에 있습니다. 서버를 여러 대로 돌리면(Vercel에서 인스턴스가 늘어날 때 포함) 대수만큼 느슨해지고, 다시 켜면 초기화됩니다.
- 같은 학교 주소를 쓰는 학생들은 주소별 제한을 함께 씁니다. 한 학생의 과도한 요청이 같은 주소의 다른 학생에게 영향을 줄 수 있어서, 주소별 값은 넉넉하게 두었습니다.
- 학생이 예전 대화 상태를 다시 보내 **같은 시점의 답변을 여러 번 받아 보는 것**은 막지 못합니다(대화별 분당 횟수 제한은 적용됩니다).
- 챗봇이 항상 프롬프트를 지킨다는 보장은 없습니다. 지금까지의 시험에서는 정답을 직접 말한 경우가 없었지만, 힌트가 정답에 가까워지는 경우와 학생 질문의 결함을 먼저 알려 주는 경우가 있었습니다.
- 위기 신호 표시는 키워드 검사입니다(2번 참고).
- 학번 카드는 학번만으로 저장·불러오기를 하므로, 수업 코드를 아는 사람이 다른 학생의 카드를 보거나 그 학번으로 저장할 수 있습니다(2-1).
- 응답을 기다리는 중에 취소하거나 시간 제한을 두는 기능은 없습니다.
- **이어서 새 대화:** 대화가 한도에 닿거나, 만료되거나, 프롬프트를 바꿔 이어갈 수 없게 되면 학생 화면에 **이어서 새 대화 시작** 버튼이 나옵니다. 누르면 화면이 지난 대화를 정리해(지금 단계, 학생이 쓴 글 전부(길면 가운데를 줄임), 챗봇의 최근 말 3개, 2차시는 1차시 카드도) 새 대화의 첫 메시지와 함께 보내고, 챗봇은 그 단계부터 이어 갑니다(세 차시 프롬프트의 '이전 대화 이어 하기' 규칙). 화면과 내려받은 파일에는 "여기부터 이어서 새 대화" 구분선이 남습니다. 정리는 학생 화면이 만드는 것이라 학생이 고친 글을 보낼 수도 있지만, 학생이 직접 쓰는 글과 같은 정도의 영향만 줍니다.
- 학생 대화는 그 브라우저 탭에만 저장됩니다. 탭을 닫거나 "처음부터 다시"를 누르면 사라지므로, 남겨야 하는 대화는 위쪽 **대화 내려받기**로 파일(.txt)로 저장하게 하세요. 교사가 모든 대화를 따로 보관하려면 대화 기록 저장(2번)을 켜야 합니다.
- 대화가 길어질수록 매 턴 이전 대화 전체를 다시 보내므로 턴당 비용이 늘어납니다. 이전 대화 부분은 프롬프트 캐시로 처리되어(Opus 5.5에서 캐시 읽기는 입력 가격의 1/20), 학생이 5분 안에 다음 글을 보내면 캐시가 이어집니다.
