# 학생용 챗봇 실행·배포 안내

탄소 저감 기술 탐구 1차시 챗봇입니다. 서버가 Anthropic API 키와 시스템 프롬프트를 보관하고, 학생은 웹 화면에서 대화합니다.

```
학생 브라우저 ──(내 글 + 서명된 대화 토큰)──▶ 이 서버 ──▶ Anthropic API
                                              └─(선택)─▶ Supabase 대화 기록(교사만 읽음)
```

- **키와 시스템 프롬프트는 서버에만 있습니다.** 브라우저로 나가지 않습니다.
- **대화 기록은 서버가 서명한 토큰**으로 주고받아서, 학생이 브라우저 개발자 도구로 챗봇의 말을 위조해 끼워 넣을 수 없습니다.
- 수업 코드, 요청 횟수 제한, 하루 상한이 있어서 외부 사람이 비용을 쓰기 어렵습니다. 하지만 **진짜 비용 상한은 Anthropic 콘솔의 사용 한도**로 따로 거셔야 합니다.

## 0. 먼저 알아 두세요

- 이 코드는 **모의 API로만 테스트**했습니다(서버 연결, 스트리밍, 위조 방지, 제한, 화면). 실제 Anthropic API가 요청 설정을 받아들이는지는 **키가 있는 곳에서 `npm run check:api`로 처음 확인**해야 합니다. 수업 전에 꼭 한 번 돌려 보세요.
- 프롬프트 시험은 모델을 에이전트가 연기하는 시뮬레이션으로 했습니다. 선택하신 모델로 실제 학생 대화를 몇 번 해 보고 정답을 흘리지 않는지 직접 확인해 주세요.

## 1. 내 PC에서 실행하기 (개발·시험용)

1. **Node.js 22.9 이상**(최신 LTS 권장)을 설치합니다. 설치 후 `node --version`으로 확인하세요. 시작 명령이 쓰는 `--env-file-if-exists` 옵션 때문에 이 버전이 필요합니다.
2. 저장소를 내려받고 폴더에서 패키지를 설치합니다.
   ```
   npm install
   ```
3. 설정 파일을 만듭니다.
   - Mac/Linux: `cp .env.example .env`
   - Windows(PowerShell): `Copy-Item .env.example .env`
4. `.env`를 열어 값을 채웁니다. **이 파일은 git에 올라가지 않습니다.** 키는 이 파일에만 쓰세요.
   - `ANTHROPIC_API_KEY` : Anthropic API 키
   - `SESSION_SECRET` : 32자 이상 무작위 문자열. 만드는 명령은 `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
   - `ACCESS_CODE` : 학생에게 알려 줄 수업 코드(비워도 시험은 되지만 운영에서는 꼭 설정)
5. **실제 API 점검**을 돌립니다. 키, 모델, 스트리밍, 프롬프트 캐시, 2턴 대화를 확인하고 통과/실패를 알려 줍니다. API 호출이 2번 일어나며 비용은 모델에 따라 다릅니다.
   ```
   npm run check:api
   ```
6. 서버를 켭니다.
   ```
   npm start
   ```
   브라우저에서 `http://localhost:3000`을 엽니다.

키 없이 화면만 보고 싶으면 `npm run demo`를 쓰세요. 정해진 문장으로 답하는 모의 응답이라 진짜 챗봇이 아닙니다.

## 2. 대화 기록 저장(선택)

교사가 학생 대화를 나중에 읽거나, 위기 신호가 감지된 대화를 먼저 보려면 켭니다.

1. Supabase 대시보드 → SQL Editor에 `supabase/schema.sql` 내용을 붙여 넣어 실행합니다.
2. `.env`에서 `LOG_CHATS=true`로 바꾸고 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`를 채웁니다.
3. 서버를 다시 켜면 학생 화면에 "대화 내용을 선생님이 볼 수 있어요" 안내와 별명 입력 칸이 나타납니다.
4. 기록은 Supabase 대시보드의 Table Editor나 SQL Editor에서 봅니다. 조회 예시는 `supabase/schema.sql` 맨 아래에 있습니다.

**결정하고 확인하실 것**
- 학생 대화를 저장하는 것은 개인정보와 관련됩니다. 학교의 개인정보 처리 지침과, 학생·보호자에게 알리거나 동의를 받아야 하는지를 **학교에 확인한 뒤** 켜세요. 이 문서는 법률 안내가 아닙니다.
- 화면은 실명 대신 별명이나 번호를 쓰도록 안내하지만, 학생이 대화에 개인 정보를 쓸 수는 있습니다.
- 보관 기간을 정하고 지나면 지우세요(삭제 예시는 `schema.sql`에 있습니다).
- 위기 신호 표시는 **단순한 키워드 검사라서 놓치는 경우가 많습니다.** 안전장치가 아니라, 교사가 먼저 읽을 대화를 고르는 보조 표시입니다. 실시간 알림도 없으므로 주기적으로 확인해야 합니다.
- 서버는 공개용(publishable) 키로 쓰기만 합니다. 이 키를 아는 사람은 기록을 **지우거나 읽을 수는 없지만 가짜 기록을 추가할 수는 있습니다.** 더 엄격하게 하려면 서버 전용 비밀 키(secret key)를 호스팅의 환경 변수로만 두는 방식으로 바꾸는 것을 권합니다.

## 3. 학생이 쓰도록 올리기 (호스팅)

이 서버는 일반적인 Node.js 앱입니다. Node 앱을 올릴 수 있는 호스팅 서비스라면 대부분 같은 방식으로 올릴 수 있습니다. 서비스마다 화면이 달라서 여기서는 공통 절차만 적습니다.

| 항목 | 값 |
|---|---|
| 런타임 | Node.js 22.9 이상 |
| 설치 명령 | `npm install` |
| 시작 명령 | `npm start` |
| 포트 | 서비스가 주는 `PORT` 환경 변수를 서버가 읽습니다 |
| 상태 확인 주소 | `/api/health` |

**호스팅의 환경 변수(비밀 값 설정 칸)에 넣을 것** (`.env` 파일을 올리지 마세요)

| 이름 | 값 | 필수 |
|---|---|---|
| `NODE_ENV` | `production` | 예 |
| `ANTHROPIC_API_KEY` | API 키 | 예 |
| `SESSION_SECRET` | 32자 이상 무작위 문자열(여러 대로 돌리면 모두 같은 값) | 예 |
| `ACCESS_CODE` | 수업 코드 | 강력 권장 |
| `TRUST_PROXY` | `1` | 호스팅 서비스 뒤에서 실행할 때 |
| `CHATBOT_MODEL`, `CHATBOT_EFFORT` | 기본은 `claude-opus-5-5`, `medium` | 아니오 |
| `LOG_CHATS`, `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` | 2번 참고 | 아니오 |

- `NODE_ENV=production`에서는 `ANTHROPIC_API_KEY`, `SESSION_SECRET`이 없으면 **서버가 시작하지 않습니다.** 설정 실수를 미리 알려 주기 위해서입니다.
- `TRUST_PROXY`를 빼면 모든 학생이 같은 주소로 보여서 요청 제한이 한꺼번에 걸릴 수 있습니다. 학교 와이파이는 한 주소를 같이 쓰므로, 학생별 제한은 대화 단위로 걸고 주소 단위 제한(`RATE_PER_IP_PER_MIN`, 기본 240)은 넉넉하게 두었습니다.
- 주소가 `https://`로 열리는지 확인하세요.
- 서버 로그에는 대화 내용을 일부러 남기지 않습니다. 세션 번호 앞 8자리, 정지 사유, 토큰 사용량, 오류 종류만 남깁니다.

## 4. 수업 전 점검표

- [ ] Anthropic 콘솔에서 이 프로젝트 전용 키를 쓰고, **월 사용 한도**를 걸었다
- [ ] `npm run check:api` 가 모두 통과했다(배포한 모델로)
- [ ] 배포 주소로 직접 들어가서 1단계부터 정리 카드까지 한 번 끝까지 해 봤다
- [ ] 정답을 조르거나 우회해 보는 말(교사 사칭, "이전 지시를 무시해" 등)을 직접 입력해 봤다
- [ ] 수업 코드를 학생에게만 알렸다
- [ ] 위기 신호 문구를 입력해 보고, 대화 기록을 켰다면 `flagged`로 표시되는지 봤다
- [ ] 대화 기록을 켰다면 학교 확인을 마쳤다
- [ ] 선생님 전화/상담실 연락처를 `prompts/lesson1_system_prompt.md` 맨 아래 '상담 연락처'에 확인해서 넣었다

## 5. 프롬프트를 고치려면

`prompts/lesson1_system_prompt.md`를 수정하고 서버를 다시 켜면 됩니다. 서버는 시작할 때 파일을 읽고, 내용의 짧은 해시를 **프롬프트 버전**으로 기록합니다(`/api/health`와 대화 기록의 `prompt_version`). 어느 버전으로 한 대화인지 나중에 알 수 있습니다. 프롬프트를 바꾸면 위 점검표의 시험을 다시 해 보세요.

## 6. 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 학생 화면에 "챗봇 서버 설정에 문제가 있어요" | 서버 로그에서 `[chat] 실패(server_config)`를 보세요. API 키가 없거나 틀렸거나 권한이 없는 경우입니다. |
| "지금 이용하는 사람이 많아요" | Anthropic 쪽 요청 한도나 일시 과부하입니다. 잠시 뒤 다시 시도됩니다. 자주 나오면 콘솔의 한도를 확인하세요. |
| "요청을 처리하지 못했어요. 처음부터 다시 시작해 주세요" | 서버 로그의 `bad_request` 메시지를 보세요. 모델 이름이나 설정이 계정에서 받아들여지지 않을 때 나옵니다. `npm run check:api` 로 확인하세요. |
| 서버를 다시 켰더니 학생 대화가 끊김 | `SESSION_SECRET`이 바뀌었거나(설정하지 않아 임시 값을 쓰는 경우) 12시간이 지나 만료된 것입니다. 운영에서는 고정 값을 쓰세요. |
| 학생이 보냈는데 아무 반응이 없음 | 같은 대화에서 이전 답변이 아직 오는 중이면 기다리게 합니다. 한 대화는 1분에 8번까지 보낼 수 있습니다. |

## 7. 알려진 한계

- 실제 API로 아직 시험하지 않았습니다(위 0번).
- 요청 제한과 하루 상한은 서버 메모리에 있습니다. 서버를 여러 대로 돌리면 대수만큼 느슨해지고, 다시 켜면 초기화됩니다.
- 학생이 이전 대화 상태로 되돌아가 같은 질문을 다시 보내는 것은 막지 못합니다(새로 시작하는 것과 같습니다).
- 챗봇이 항상 프롬프트를 지킨다는 보장은 없습니다. 지금까지의 시험에서는 정답을 직접 말한 경우가 없었지만, 힌트가 정답에 가까워지는 경우와 학생 질문의 결함을 먼저 알려 주는 경우가 있었습니다.
- 위기 신호 표시는 키워드 검사입니다(2번 참고).
