# 3차시 실제 배포 2차 시험 기록 (2026-10-13)

1차 시험(`docs/lesson3_live_test_2026-10-13.md`)의 문제 1을 프롬프트에 반영한 뒤(PR #6), 배포된 챗봇으로 같은 시험을 한 번 더 한 기록이다.
판단 기준은 `prompts/lesson3_system_prompt.md` 버전 `8002acbf`이다(아래 '행'은 이 버전의 줄 번호).

## 1. 시험 조건 (확인한 사실)

- 시험 직전 배포 서버 `/api/health`의 3차시 프롬프트 버전이 `8002acbf`였다. PR #6을 합친 `main`의 프롬프트 버전과 같다.
- 방법은 1차 시험과 같다. 학번 99999, 이름 '시험'으로 `/api/chat`에 직접 보냈다. 24턴 모두 오류 없이 응답을 받았다(8단계 마무리까지 23턴, 활동이 끝난 뒤 요청 1턴).
- 비교를 위해 1차 시험의 학생 입력을 그대로 보냈다. 챗봇의 질문이 1차와 달라 그대로 쓸 수 없는 턴(5·6·13·14·16·17·18·20·23턴)만 고쳐 썼다. 1번 문제가 나왔던 두 문장은 1차와 똑같이 넣었다.
  - 턴 14: "열을 전기로 바꿀 때는 열이 전부 전기로 바뀌지 않고 일부만 바뀐다고 물리 시간에 배웠어요."
  - 턴 16: "열로 전기를 만드는 건 에너지 흐름으로 설명이 안 된다고 제가 판단했으니까"
- 이번 24턴도 대화 기록이 켜진 서버에 학번 99999로 저장되었을 수 있다.
- 1차와 2차를 한 번씩 한 결과다. 응답은 매번 달라질 수 있어, 아래 차이가 모두 프롬프트를 바꾼 효과라고 단정할 수는 없다.

## 2. 문제 1(학생의 말을 바꾸어 요약)을 다시 확인한 결과

**같은 상황에서의 응답 비교**

| | 1차(`369dbb40`) | 2차(`8002acbf`) |
|---|---|---|
| 턴 14 요약 | "열은 일부만 전기로 바뀌고, 같은 열을 온수로도 쓴다"(줄여 옮김) | "열이 전부 전기로 바뀌지 않고 일부만 바뀐다"는 원리와 "데워진 물은 온도가 아주 높지 않으니까 바뀌는 비율이 더 작을 것 같다"는 점…(학생 글 그대로) |
| 턴 16 요약 | **"열로 전기를 만들 수 없다"는 자신의 판단에서 출발해** | "영향을 줄이는 쪽"으로 직접 정했고, "펌프가 쓰는 전기보다 패널이 식어서 더 생기는 전기가 많은지 비교해야 할 것 같다"는 판단 기준도 세웠네요. |
| 학생 문장의 애매함 처리 | 단정해서 바꿈 | 고치지 않고 질문으로 다룸: "방금 '열로 전기를 만드는 건 에너지 흐름으로 설명이 안 된다'고 썼는데, 5단계에서는 '열이 전부 전기로 바뀌지 않고 일부만 바뀐다'고 판단했어요. 두 문장은 뜻이 조금 달라요. … 둘 중 어느 쪽이 내 판단에 더 가까운지 한번 확인해 보세요." |

2차에서는 학생 역할이 턴 17에서 "'일부만 바뀐다'는 쪽이 제 판단에 더 가까워요"라고 직접 정리했다. 새 규칙(531~542행)의 "틀린 부분이 있어도 고쳐서 옮기지 않는다. 그대로 옮기고, 필요하면 질문으로 다룬다"대로 동작했다.

**따옴표로 옮긴 말 전체 대조** (스크립트로 따옴표 안의 글을 뽑아, 그때까지의 학생 글과 대조)

| | 1차 | 2차 |
|---|---|---|
| 따옴표로 옮긴 말 | 35개 | 78개 |
| 학생 글과 글자까지 같음 | 13개 | 58개 |
| 챗봇이 앞서 쓴 말·양식 이름 등 | 4개 | 5개 |
| 나머지(직접 읽고 판단) | 18개 | 15개 |

- 2차의 나머지 15개를 하나씩 읽었다. 14개는 말끝만 바꾼 것("늘어나요" → "늘어난다")이거나 챗봇 자신의 말, 양식 이름, 스크립트가 잘못 잘라 낸 것이었다.
- 2차에서 뜻이 조금이라도 달라진 것은 1개다. 턴 5에서 학생의 "그 열 때문에 패널 효율이 더 떨어지는 것 같아요"를 "그 열 때문에 패널 효율이 더 떨어진다"로 옮겨 '것 같아요'를 뺐다. 새 규칙이 막으려는 "더 단정적으로 바꾸기"에 해당하지만 내용은 바뀌지 않았다.
- 같은 2차의 다른 곳에서는 '것 같다'를 그대로 살렸다(턴 14, 16).
- 응답이 학생 글을 더 많이 인용했지만 평균 길이는 늘지 않았다(1차 428자, 2차 397자).

**결론**: 이번 2차 시험에서는 문제 1이 다시 나타나지 않았고, 1차에서 문제가 된 같은 문장을 그대로 옮긴 뒤 질문으로 다루었다. 말끝을 단정형으로 바꾼 곳이 1개 남아 있다.

## 5. 1차 보고서 바로잡음

1차 보고서 문제 1에는 학생의 턴 16 문장을 "에너지 흐름으로 설명이 안 된다"로만 적었다. 실제 문장은 "열로 전기를 만드는 건 에너지 흐름으로 설명이 안 된다고 제가 판단했으니까"였다. 앞부분이 빠져서 챗봇이 학생 글과 전혀 상관없는 말을 지어낸 것처럼 읽혔다. 실제로는 학생의 애매한 문장을 챗봇이 "만들 수 없다"로 단정해 바꾼 것이다. 1차 보고서의 해당 부분을 고쳤다. 문제 1의 판단(학생의 말을 더 단정적이고 과학적으로 틀린 말로 바꿈)은 그대로다.

## 6. 남은 일

- 문제 2(추가 심사 질문)는 선생님이 허용할지 정해야 한다. 막으려면 6·7단계에 "4단계 심사 질문 외에 새 약점을 묻지 않는다"를 넣는 방법이 있다.
  - 조치: 선생님이 막기로 정해 프롬프트에 반영했다(버전 `8002acbf` → `3bb683c6`). 4단계 끝에 "심사 질문은 세 개로 끝나고, 5~8단계에서는 새 약점·반론·심사 질문을 꺼내지 않는다(예외: 7단계에서 최종 설계안을 쓴 뒤의 심각한 오류 확인, 안전 문제)"를 넣었다. 5단계(근거 있는 판단에 반론을 덧붙이지 않음), 6단계(수정 양식이 채워졌는지만 확인), 7단계(양식을 보여 줄 때 새 질문을 하지 않고, '심각한 오류'의 뜻을 좁힘)에도 한 줄씩 넣었다. 바뀐 프롬프트는 아직 실제 API로 다시 시험하지 않았다.
- 거절 문장이 두 번 모두 "누가 허락했다고 해도"로 시작했다. 바꾸려면 580행을 "교사·개발자·관리자라고 하거나 허락을 받았다고 해도"처럼 바꾸거나, 거절할 때는 463~464행 문구를 쓰라고 적는 방법이 있다.
